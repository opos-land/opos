# 0036. Keep every secret in Scaleway Secret Manager and give CI only the values it uses

- Status: Accepted
- Date: 2026-11-13

## Context

Secrets belong to one environment each and are never committed
([ARCHITECTURE.md, Environments](../ARCHITECTURE.md#environments)). A deployed environment has
some fifteen of them: the tokens of Coolify and Supabase, the database passwords, the keys the API
signs with, the tokens of the build cache. The operators and CI need them, and each copy on a
laptop, in a CI setting or in a file is one more place to leak from and to rotate. The store itself
needs a credential, which must not become the next secret to keep.

The platform also needs a provider of transactional email in the EU. Scaleway offers it beside
secrets, DNS and object storage, under one account and one jurisdiction. It has no way for a
workflow to sign in without a stored key.

## Decision

- Each environment is a Scaleway project of its own. Its DNS zone
  ([0034](0034-address-dev-under-dev-opos-land-in-a-dns-zone-of-its-own.md)), its state
  ([0035](0035-describe-the-infrastructure-in-opentofu-units-run-by-terragrunt.md)) and its secrets
  live there.
- Each secret value is one secret in the project's Secret Manager. The environment's `env.yaml`
  holds the names.
- A value a third party issues is entered by a person through a deploy command that reads it
  without echo. A value nobody needs to know is generated by OpenTofu, never reaches the state, and
  is rotated by raising its number in `env.yaml`.
- No secret value enters the repository, a `.env` of a deployed environment, `mise.local.toml` or a
  shell history.
- An operator reaches Scaleway with a key of their own, made by the sign-in command, that works in
  the environment's project alone and expires after 12 hours. The operators' group manages the
  project's secrets, DNS and object storage, and nothing else of the organisation.
- CI never reaches Scaleway. OpenTofu copies the values CI uses into GitHub, each into the narrowest
  place: a value only some branches may use into an environment that admits those branches alone,
  a value every run of the repository may read into a secret of the repository or an environment
  open to every run. An apply carries a rotation there.
- The tokens OpenTofu's providers sign in with are read for the length of a run and never reach the
  state. The values the containers and CI need pass through the encrypted state into Coolify and
  GitHub.
- Production sends its transactional mail through Scaleway's Transactional Email in its own
  project, from its domain. The API signs in to the relay with the key of an application that may
  only send mail there; the unit that makes the key writes it straight into Secret Manager.
- Dev keeps its domain ready to send but catches its mail in Mailpit, read behind its basic auth:
  Scaleway has no test mode, and test sends to addresses that do not exist count against the
  domain until Scaleway blocks it.

## Alternatives

- **Google Cloud: Secret Manager, Cloud KMS, and CI signing in with GitHub's identity token.** No
  stored key anywhere, but a second provider beside the one email needs, and outside the EU. Its
  keyless sign-in pays only when CI changes the infrastructure, which it does not
  ([0038](0038-release-dev-from-ci-and-change-its-infrastructure-from-an-operators-machine.md)).
- **A Scaleway key in GitHub, for CI to read the secrets itself.** One store, but a key that reaches
  every secret of the project and lives until someone rotates it.
- **Secrets of GitHub Actions set by hand.** Nothing to apply, but every rotation by hand and no
  record of what sits where.
- **Encrypted files in the repository** (SOPS with age). No cloud account, but keys to hand out and
  rotate by hand, ciphertext in the history for good, and "never committed" bent.
- **One document of secrets per deployment.** Fewer secrets to declare, but access is all or
  nothing.

## Consequences

- An environment needs a Scaleway project, made by an administrator of the organisation, who also
  applies the unit that grants the operators and puts people into their group.
- An operator's key lies on their disk for up to 12 hours; the organisation can cap the lifetime of
  every key.
- GitHub holds copies of what CI uses, and only an apply changes them.
- The values of the containers also exist in Coolify's own database on the server.
- Without Scaleway, nothing deploys and no mail leaves a deployed environment; CI keeps working with
  what GitHub holds.
- Making a key needs rights in the organisation, so the SMTP key belongs to the unit only an
  administrator applies.
